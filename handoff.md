## 8. Conventions (condensed, unchanged)

- **Overlay workflow**: sandbox edits the tree → overlay **zip of changed files** (regular rounds; bundles only for upstream merges) → owner applies as own commits → llvm-mingw i686 Win11 build (MSYS2 MINGW32, ~501 targets). The full build is the owner's gate.
- **VP-BEGIN/VP-END markers** on every fork edit in upstream files; fork-only TUs (`VanillaPlusCore.{h,cpp}` at `D2Client/UI/`) keep upstream files free of new code.
- Every source change updates the `tools/check-vanilla-plus.sh` gate table. (The owner-side fork-surface budget/allowlist check is RETIRED rev43; main never sends PRs, clean branches off main carry PR hygiene.)
- Line endings: **merged main is LF-normalized** (rev41 finding) — patchers detect and preserve each file's ending, never mix.
- **Version self-ID** (`Application.cpp:66`) bumps every code round so d2boot.log pins the build; docs-only rounds do NOT bump it. The suite carries a single self-ID row, repinned every round; the build check itself is manual: d2boot.log line 1 (SMOKE-CHECKLIST item 0).
- **Sandbox**: llvm-mingw i686 cross-toolchain available since R90b (full cross-build proof: 487/487 objects, `d2.exe` links pei-i386) — no apt; **the owner's MSYS2 build stays the compile gate of record.** Per-round changed-TU compile checks must pass the CMake forced-include set (`-include d2_platform.h -include support/d2_hand.h`).
- Diagnostic channels: `d2boot.log` (`[d2boot]` marks, permanent), hangwatch stall dumps, the game log (`DirectSound error:` lines), `glide3x.log` (wrapper side). Sandbox tooling of record: the per-round `scripts/compile_check_rNN.sh` series + the R85/R86 harnesses + the R87/R88 merge-triage census scripts + the R104 `fork_surface_syntax_sweep.sh` (sandbox-side, not part of the build).
