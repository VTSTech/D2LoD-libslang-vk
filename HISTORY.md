## H3. The sound-defect series — full record (2026-10-26/27, CLOSED + upstreamed)

Two defects after the eleven; retail 1.14d Game.exe's sound code (the user's Ghidra decompiles) is the reference throughout. Status at archive time: both fixed on vanilla-plus, both shipped upstream via **jaenster/redivivus PR #10** (branch `pr4/sound-except-intro`, 3 commits, merge-clean at filing).

**Defect 12 — title/in-game music silent (CLOSED, field-verified).** Intro-video (Bink) audio was always audible — separate path. Every DDA/SFile music buffer sat at DSBVOLUME_MIN (-10000) from its first feed. Root cause: **Ghidra prints double constants as IEEE-754 bit patterns, and the port transcribed them as hex *integer* literals.** `0x3f1a36e2e0000000` is the double `0.0001` (the clamp epsilon — as an integer ≈7.3e19), `0x409f400000000000` is `2000.0` (the centibel scale); pasted as integers, `SOUNDSMP_ClampVolume`'s `value <= min + eps` fired on every input and every conversion returned -10000. The R5 scale fix (-2000.0) sat *behind* that clamp and never executed — which is why the fcd50d8/ce32a18 rounds changed nothing. Fixed five literals in `D2Sound/Src/D2SoundSmp.cpp` (two ClampVolume epsilons; ClampAttenuation epsilon, bottom bound, divisor — the old bottom bound `(double)-0x3f3c780000000000` actually decodes to -0.0004344, a third casualty; `-10000.0` is the retail curve's real bottom). Commit `d86ba98` = user's `4031fa7` "R6 fix". Field: "Music works now! Both at title and in game."

Retail volume-curve reference (user-supplied FUN_005165f0), now reproduced exactly: `value ≤ min+0.0001 → -10000`; `value ≥ max-0.0001 → 0`; else `-2000·log10((max+min)/value)` centibels. Verified: 255→0, 110→-730, 0→-10000; `SOUNDSMP_ClampAttenuation` (10^(att/2000)) is its exact inverse. DirectSound: volume -10000 = absolute mute, 0 = full; hr 0 = SetVolume succeeded.

**Defect 13 — NPC speech + monster/player SFX silent (CLOSED — fix 16 `9c8beb9`, field-verified).** Symptom was: "Still no NPC Speech or Monster/Player sounds." R6 log ground truth: Warriv speech **does** stream+play (`DATA\LOCAL\SFX\common\warriv\war_goodday.wav`, dda PLAY#3) but post-open GetVolume = -10000 → the **client-side** volume chain writes silence. Music is unaffected (own volume source). Client chain: `SOUND_PlaySound` (D2Client/Sound/Sound.cpp:5441, request) → tick → `SOUND_PlaySoundWithPanning` (GAME/Sound.cpp:634) → `SOUND_UpdateChannelParams` (GAME/Sound.cpp:410, volume) → SetVolume/OpenAndStreamFile.

**The SMP layer is EXONERATED (2026-10-27).** User supplied retail decompiles of all four FUN_005165f0 callers — FUN_005157b0 SmpSetVolume, FUN_00515890 SmpSetPan, FUN_00515a90 SmpSetEaxObstruction, FUN_00515b40 SmpSetEaxRoomLevel — plus the complete call-site list (5 sites inside the same four functions). The port matches retail on every axis: halt IDs (0x2cb/0x2ef/0x345/0x359), `D2SoundSmpStrc` offsets (pDSBuffer@0x00, pEaxInterface@0x10, dwFlags byte@0x34 bit 2, nVolume@0x38, fEaxObstruction float@0x3c, size 0x60), float literals (0x437f0000=255.0f, 0x42fe0000=127.0f, 0x3f800000=1.0f), the master multiply `gnSoundGlobalVolume × vol / 255` with store-to-nVolume, the quality-flag==2 attenuation skip, and EAX property IDs 7 / 1 / 5+4 with 4-byte payloads. **Do not re-audit the SMP layer.**

**Resolution (R7 → R8 → fix 16).** R7 log (title + Act 1 town): every non-stream sound's `updchan:` ended `vol=0` while its inputs were non-zero (b1c 125–255, svol 90–255, even an mvol=1/b38=2 channel) → SetVolume att=-10000; music escaped via the dedicated stream+fade path (`fadein:`/`fadevol:` ramps; town1 sid=4673 landed att=-1348 = att of its pre-Calc volume, exactly as the retail curve predicts). R8 log (floats re-logged as IEEE bit patterns after R7's `%f` printed literal `f`): the client's PRE-Calc volume was **healthy** (mv=100 muv=50 lcv=100 rcv=100; pre-Calc vol 125–220), and war_goodday.wav (sid=4325) landed att=-10000 through an open path that writes no volume — pinning the zero inside the single `SOUNDSMP_CalculateVolumeAndPan` call site (the `if (!pSoundChannel[1])` block in `SOUND_UpdateChannelParams`). **Root cause:** the call passed `(uint32_t*)&fFalloffMin / &fFalloffMax` — the *storage of two float locals* — and the block read the results back AS FLOATS: `(int)fFalloffMin` for the volume multiply, `(int32_t)fFalloffMax` for SetPan. Any CalcVol in 0..255 has IEEE bits `0x000000xx`, which reinterprets as a subnormal float (~1e-43) and truncates to 0 → volume 0 for EVERY channel taking the block; music-flagged channels (`pSoundChannel[1] != 0`) skip it — exactly the observed music-vs-SFX split. **Fix 16** (`D2Client/GAME/Sound.cpp`): receive the out params as proper `uint32_t nCalcVolume / nCalcPan` locals and use them for `SOUNDSMP_SetPan` and the `nCalcVolume * preVol / 0xff` multiply — retail integer semantics, no float round-trip. Field: "The sounds works now. NPC's Monsters, Player. All working."

**Known open deviation (carried forward as a handoff watch item): stereo position only, NOT a silence cause.** Our `SOUNDSMP_SetPan` right-branch negates (`SetPan((int)-fVar1)`); retail as-decompiled passes the raw (negative) conversion result to vtable+0x40. Retail's slot may be a wrapper Ghidra flattened — identify the retail owner before touching; do not "fix" blind.

**Upstream record (2026-10-27).** Issue + PR filed on jaenster/redivivus: **PR #10** ("Sound: only the intro video had audio — bind DirectSound to the game window, decode FP bit-pattern constants, read CalculateVolumeAndPan's integer out params as integers"), head `VTSTech:pr4/sound-except-intro` → base `main` @ `eef5f2c`, 3 commits / 3 files, `mergeable_state: clean` at filing. ## H8. Delivery conventions — full historical text (current condensed rules live in handoff §6)

**The overlay model (glide era).** Deliverable = zip in `/home/z/my-project/download/`: `OVERLAY-PR2-FIXN.md` (root cause, evidence table, self-diagnosis greps, decision tree, branch matrix vanilla-plus vs pr2) + `patches/PATCH.diff` (normalized prefixes, minimal hunks) + `drop-in-pr2/` and `drop-in-vanilla-plus/` full files (fallback route). QA gauntlet (all green before shipping): `git apply --no-index` round-trip **byte-identical** on *every* supported base (`GIT_CEILING_DIRECTORIES=/home/z/my-project`); **negative test** — the patch must *refuse cleanly* on an already-fixed tree; unique-anchor asserts for every edit site on every base; new C++ files `g++ -fsyntax-only -Wall -Wextra` against stub headers; builders persisted as scripts.

**The fix-11 lesson, burned in:** the fix-11 zip's vanilla-plus drop-in was cut from the pre-fix-10 tip, so the user's whole-file copy reverted nine u32 stores and the light-radius discoloration returned in the next build (root-caused byte-level in Task 20; fixed by fix 12). Rules going forward: **patch-first** (full-file drop-ins fallback only); drop-ins must be cut **from the tip the user actually has** — verify with a base-state grep gate printed in the OVERLAY.md (e.g. `grep -c "glide fix 10" D2Glide/Renderer/Glide.cpp` → 0 = regressed, ≥1 = intact); deltas touching the same file must be QA'd order-independent.

**Git bundles (rev 4 route).** The sandbox has no push credentials, but whole commits transfer as bundles — history, authorship and fast-forward arrive intact:
```
git bundle create download/<repo>-vanilla-plus-<tip7>-bundle-<date>.bundle origin/vanilla-plus..vanilla-plus
# user side: git fetch <file>.bundle vanilla-plus && git merge --ff-only FETCH_HEAD && git push origin vanilla-plus
```
QA: `git bundle verify` in the sandbox clone AND in a scratch repo initialized at exactly the prerequisite tip; fetch+`--ff-only` must fast-forward cleanly, then content greps for every fix claimed; the prerequisite is the user's **pushed** tip — check `git rev-parse origin/vanilla-plus` AFTER a fresh `git fetch origin`, never from a stale remote-tracking ref (bit once: scratch was built at 9389e07 while the user was already at 0fa2003). Record bundle path + prerequisite + verification in the worklog.

**tmpfiles.org overlay zips (rev 5 route, the working loop since CI retirement).** Overlay zips of **only the files actually changed** — never a stale whole-file overlay (the user's tree carries their own commits; cut every delivery from a fresh `git fetch origin`). Zip layout: `<changed files at repo-relative paths>` + `MANIFEST.txt` (base commit, per-file sha256, base-state grep gates, apply/build steps, acceptance criteria). Upload to tmpfiles.org (**60-minute expiry**); the URL curl receives is an **HTML interstitial** — extract the tokenized `/dl/<token>` link embedded in that page, then **byte-verify** (`curl -o /tmp/f <dl-url> && cmp /tmp/f <local-file>`) and record the sha256. Post the `/dl/` link, never the interstitial URL.

**format-patch route (rev 7, used for upstream PR #10).** For PR-style deliveries: build the commits in a scratch worktree at the target base, `git format-patch <base> -o download/<dir>/`, `sha256sum *.patch > MANIFEST.sha256`, zip the directory, QA with `git apply --check` in sequence on a pristine checkout of the base, then diff -r the QA tree against the commit tree (must be identical).

## H12. Fullscreen D3D round 4 — intro plays, then HALT 0xd7: phantom sprite-cache structs (2026-10-28, fix 20)

Post-fix-19-rev-2 boot was the breakthrough round: `CreateWindowWithChecks -> 1` (the Error-25 wall that started the whole hunt, retired), provider init/InitPerspective/pre-setup all `-> 1`, and the intro video **plays with music** in fullscreen D3D. Then ~5.1s after mode-loop entry: clean `HALT line=215 (0xd7)` at addr 0116E8F3, followed by a secondary VEH 0xC0000005 during error-path cleanup (expected to vanish with the halt fixed — the halt path tears down a half-initialized device; if a halt-cleanup AV ever recurs, take it from the d2crash stack).

The decode took one grep: the only `0xd7` halt in the tree is `D3DTEXCACHE_AllocateNodeFromFreeList` (d3dTextureCache.cpp:101) — free list empty (`pFreeHead == 0`) while `nUsedCount != nMaxNodes`, an invariant-violation halt. Analysis of the module: `D3DTEXCACHE_EnsureAvailableNode`'s eviction loop cannot rescue a never-seeded cache (nUsedCount 0 skips eviction → retry hits the same empty free list), and a *negative* `nMaxNodes` (bad memory math) was eliminated because the seed's `D2_ALLOC`/`memset` would have AV'd at boot, not halted at 5s. The only remaining state was "cache struct never seeded at all".

That state is real because of a **new §1 variant — phantom function-statics**: `RENDERER_DIRECT3D_UploadTextureToCache` (Direct3D.cpp:2426) selected its cache with retail-image arithmetic — `pCache = (D3DTextureCacheStrc*)(&DAT_00970eac + class*0x1c)` and node bases via `(&INT_00970ec4)[class*7]` — where `DAT_00970eac`/`INT_00970ec4` were the export's 1-byte/4-byte remnants of the three contiguous `D3DTextureCacheStrc`s (0x1c bytes each) that live in the rebuild as `gD3DGenericTextureCache.aCaches[0..2]` (globals/D2Direct3D.cpp:2268), seeded by `RENDERER_D3D_InitializeTextureCachePool`. The upload therefore read an unseeded BSS struct: garbage `nMaxNodes`, `nUsedCount` 0, `pFreeHead` null → halt 0xd7 on the **first DC6-sprite upload** — which is exactly the first-logo boundary of the intro (Smacker frames don't use this path, which is why the video itself played).

The corrected mapping (class 1/2/3 → `aCaches[0/1/2]`, textures 0x100/0x80/0x20) is corroborated three ways: the pool sizes match the three `CreateSystemMemoryTexture` calls (`InitializeTexturePools` :3142-3152); the `D3D_PixelDataFreeCallback_ClearCacheNodes` callback (:2369-2384) already addresses the real caches with the same `aCaches[class-1]` / `pNodeBuffer[idx-1]` indexing; and the class thresholds (:2457-2466: ≤0x20→3, ≤0x80→2, ≤0x100→1) match the pool texture sizes. Fix 20 replaces the phantom arithmetic with `pCache = &gD3DGenericTextureCache.aCaches[iMipLevel - 1]` + a `pCacheNodeBase = pCache->pNodeBuffer` local at all four `INT_00970ec4` sites, and deletes the two phantom statics. A repo-wide sweep for `DAT_/INT_/UNK_` label arithmetic found exactly one other suspect — `Storm/_unnamespaced.cpp:789` `INT_007a6b0c = (int)(1000 / (int64_t)gaKeyBindingDefaultArray)` (dividing by an array *address* is surely a mislabeled scalar) — logged as an audit item, untouched.

Footnotes from the same read: (1) `apSpriteTextures[class+2]` (:2484) formally indexes past the 3-element array into `apSpriteSurfaces[0..2]` — correct-by-adjacency (retail's flat layout; sizes line up 0x100/0x80/0x20), fragile if the struct field order ever changes — audit note only. (2) If `GetAvailableVidMem` fails on the emulated DD7, its failures appear in the FOG log as `Failed to get available texture/local texture memory` `*****` lines and poison the pool sizing (`uSmallCacheAlloc = g_nVideoMemoryTotal`, :624/:2027) — check the FOG log if further cache halts appear. (3) This upload function alone carries 11 distinct halt codes (0x164/0x165/0x16d/0x16e/0x171/0x172/0x19a/0x19b/0x1b4/0x1b5/0x1c0) — a future halt here names its own branch. Lesson added to the §1 pattern list: **phantom function-statics (`DAT_`/`INT_` labels + raw `&label + k*sizeof` arithmetic) are extent truncations in disguise — grep for the label pattern, not just for `sizeof` mismatches.**


## H13 — Fix 21: `HALT line=365 (0x16d)` at the first sprite upload — the D3D upload path never received the glide series' sprite-header slot guards (2026-10-27, round 8)

Field: user's local build `f50099f` (fixes 17+18+19rev2+20 applied; "local builds don't always rotate commit hash" — the hash is their local commit). Fullscreen D3D boot: new clean halt `HALT line=365 (0x16d)` at `d2s-f50099f.exe+0x234188`, fault frame `+0x44840F` (Fog halt manager). Single-grep decode (round-7 precedent + the H12 footnote that predicted this): the only `0x16d` halt in the tree is `RENDERER_DIRECT3D_UploadTextureToCache` (Direct3D.cpp:2521 pre-fix-21) — **the halt code names the branch**: a freshly-acquired cache node's `pSurface` (+0x10) is null.

The round-8 analysis is a study in how far a contradiction can be pushed before the data decides. Exhaustive static audit of the D3D cache machinery found every path consistent: the seeder `RENDERER_D3D_InitializeTextureCachePool` (:5039) gives every node 0..nMaxNodes-1 a surface+texture pair via `CreateSurfaceWithTexture` (node-0 failure = halt 0x5a at boot — didn't happen; later failure truncates `nMaxNodes` coherently and zeroes the chain tail); `AllocateNodeFromFreeList`/`EnsureAvailableNode`/`InvalidateByIndex`/`InsertNodeAtTail` bookkeeping verified sound; `gD3DGenericTextureCache` zero-initialized; the per-frame descriptor blocks (0x2c bytes per DC6 frame, allocated+zeroed by `CELCMP_FixupPointersAndPrepare` :1464-1478, `[class, nodeIdx]` slot pairs at `mode*8`) legitimate retail design with all writers inside bounds; upload callers pass only modes 1/2/3/4; stack frame bands (via the round-5 map mapping) place the halt in the normal post-intro render loop, i.e. the FIRST sprite upload of the session on freshly seeded caches. Under those invariants halt 0x16d is unreachable — the state it reports cannot exist for a *seeded cache addressed with a sane class*.

The resolution: **the class is not sane.** The decisive cross-reference was in our own tree all along — `Glide.cpp:1053-1059`, the field-verified **glide fix 3** from the closed glide series: "Sprite headers come from a non-zeroing pool, so a first-use header can carry pool garbage in the size-class slot. Treat an out-of-range class like an unset one (recompute below) and zero the slot so the recompute sticks." The D3D upload path tests the class slot for **exact zero only** (Direct3D.cpp:2469 pre-fix), so a garbage slot value outside {0,1,2,3} skips the size recompute and flows into `pCache = &gD3DGenericTextureCache.aCaches[class - 1]` — **past the 3-entry array**. `D3DTextureCacheSetStrc` is packed: `aCaches[3]` aliases `apSpriteTextures[0..1]` (offset 0x54), `aCaches[4]` hits `apSpriteSurfaces` and beyond — the adjacency lottery. A pointer-shaped `pFreeHead` there is non-null (no halt 0xd7), `nUsedCount != nMaxNodes` as two different pointers-as-ints (no early return), and the "popped node" is aliased memory whose +0x10 reads zero — exactly halt 0x16d, cleanly, at the first upload with a garbage header. This is the D3D twin of glide defects 2/3/4 (the stale/garbage sprite-header slot family, ledger rows 2-4) — never ported because **the D3D upload path had never executed until this week**.

FIX 21 (Direct3D.cpp only, both guards inside `RENDERER_DIRECT3D_UploadTextureToCache`):
1. **Glide fix-3 mirror** (before the class recompute): `if (slot < 1 || 3 < slot) slot = 0;` — out-of-range class (including garbage and negatives) is treated as unset so the width/height recompute pins the class to 1..3.
2. **Glide fix-2 mirror** (after `pCacheNodeBase`, before the reuse deref): if the header's node-index slot is non-zero, validate it against the pool bound (`(uint32_t)(idx-1) < nMaxNodes` — hardened beyond glide, which dereferenced unbounded) and the node's own backpointers (+4 block ptr, +8 mip idx — both written by this very function, so a legit palette-change re-upload matches by construction); on mismatch drop the slot to 0 and allocate fresh.

Residuals/footnotes from the same read: (a) `D3D_PixelDataFreeCallback_ClearCacheNodes` (:2367-2385) acts on all five slot pairs with only a signed `>= 1` guard — a never-uploaded frame with garbage [class>=1, idx>=1] slots could still spuriously clear a node's tile pointer (or worse) at sprite-free time; glide's field-verified fix 2 left the identical residual in `GLIDE_PixelDataFreeCallback_ClearCacheNodes`, so it is mirrored as-is and logged as an audit item, not fixed. (b) The DCC combined-blob loader (`CelCmp.cpp:1398`) `D2_ALLOC`s without memset — a corroborating non-zeroing sprite-container route. (c) H12's footnote-1 adjacency note (`apSpriteTextures[class+2]` -> `apSpriteSurfaces`) is the same packed-struct layout this halt exploited maliciously at `aCaches[3+]`; correct-by-adjacency at class <=3, hostile beyond.

Institutional lesson added to the §1 pattern list: **when a code path first executes, audit it against the fixes its sibling paths already received.** The glide series closed 14 fixes deep; the D3D renderer shares the sprite-header infrastructure and inherited none of that hardening. A one-line grep ("what does the working renderer do at this exact site?") answered in seconds what hours of single-module static analysis could not — the module-internal proofs were all correct; the garbage was coming from *outside the module's invariants*.

## H14 — Fix 22: the 0x16d wall recurs through an applied fix — verify what the fix actually gates, close the proven WRITE side, and make the halt site a measurement point (2026-10-27, round 9)

Field: user's build `d2s-0604b96` (hash rotated from `f50099f` — fix 21 confirmed in; the halt site shifted +0x99, exactly the size of the added guard code, which is itself positive identification) boots identically — intro plays, mode loop entered — and clean-halts `HALT line=365 (0x16d)` at the same first-sprite-upload spot. **A fix whose target halt recurs unchanged must be treated as a falsified theory, not bad luck.** So round 9 re-verified every premise of H13's residual theory *by direct reading, this round, no reuse of round-8 conclusions*:

- Seeder `RENDERER_D3D_InitializeTextureCachePool` (:5070-5123): every free-list node gets a surface+texture; mid-seed failure truncates `nMaxNodes` AND zeroes `pPrev->pNext` coherently — no unseeded node is reachable. The "negative node count" scenario self-checks: it would AV at boot (memset through null/huge alloc), which did not happen.
- `RENDERER_D3D_CreateSurfaceWithTexture` (:2238): DD_OK ⇒ non-null surface out; QI fail ⇒ Release+FALSE. TRUE with a null out is impossible.
- `AllocateNodeFromFreeList`/`EnsureAvailableNode`/`InvalidateByIndex`/`InsertNodeAtTail`: alloc/evict/invalidate never clear node +0x10; eviction clears the owning descriptor's slot pair via the node's tile backpointer.
- Layouts: `d3dTextureCache.h` is the single definition (globals.h includes it); the packed `D3DTextureCacheSetStrc` adjacency (`apSpriteTextures[class+2]` → `apSpriteSurfaces`) is correct-by-adjacency at class 1..3.
- Descriptor truth: `CELCMP_GetDC6BlockPixelData` returns `*(block+0x18)` = the 0x2c descriptor base written by `FixupPointersAndPrepare` (memset); slots live INSIDE it; `DeleteCellFile` invokes the free callback with that same base per frame.

Verdict: **post-fix-21, halt 0x16d is unreachable through any read path.** The state it reports can only be produced by a write the read-side guards cannot see. The family's one proven unbounded write is the round-8 audit-noted residual: `D3D_PixelDataFreeCallback_ClearCacheNodes` validated each `[class, idx]` pair with only a signed `>= 1` and wrote `aCaches[class-1].pNodeBuffer[idx-1].pAssociatedTilePtr = 0` — no class range check (class > 3 indexes past `aCaches[0..2]`), no idx upper bound (unbounded wild write past the node buffer), no owner match (a stale/garbage pair cleared a foreign node's backpointer). Feeding it garbage: pairs 0 and 4 are NEVER written by the upload path, and DCC combined-blob frames (`CELCMP_SerializeCelFileToMemory`, `D2_ALLOC` without memset) carry 0x23-byte headers — 5-pair reads at +0x20 overrun into structural/pixel bytes (H13 footnote b upgraded from "corroborating" to "load-bearing"). The stride math is exact: the write lands at `base + (idx-1)*0x20 + 4`, so it can never directly zero a node's +0x10 — but out-of-range `idx` corrupts arbitrary heap, and heap corruption happily zeroes whatever the next upload pops. Cannot be proven offline; it is now closed regardless.

FIX 22 (three parts, one file + one banner):
1. **Free-callback hardening** (`D3DTEXCACHE_ClearCacheNodeSlot` + 5 validated calls): range-check class 1..3 and idx 1..nMaxNodes against the real pool, then require the node's own +4 backpointer to equal the descriptor being freed (that field is written by `UploadTextureToCache` and nothing else, so every legit free matches by construction). Legit frees behave byte-identically to retail; garbage pairs are skipped; the FIRST skipped pair of each dangerous shape (out-of-range class, out-of-bounds idx, foreign node) is reported to d2boot.log via `D2BOOT_MarkFmt` — if the field ever shows `fix22: free-callback skipped ... (was a wild write)`, the garbage-pair theory was live, not theoretical. Glide's twin callback stays as delivered (field-verified working renderer — asymmetric hardening is deliberate and noted).
2. **Halt-site self-diagnostics** (`RENDERER_D3D_UploadHaltDump` before all 12 halt sites in `UploadTextureToCache`): one d2boot.log line per site with mode/mip/class/node/sprite dims, one with the pool's identity and bookkeeping (`pool= max= used= freeHead= freeTail= usedHead= usedTail= nodes=`), one with the failing node's full contents when in-bounds, one with the class's permanent sprite texture/surface pointers. The next field round names its failing premise from the log alone — no more blind fix rounds at this wall.
3. **Fixset boot banner** (`vanilla-plus fixset through fix 22`, Application.cpp): field logs self-identify the fix level regardless of commit-hash rotation — the "local builds don't always rotate the hash" confusion cost this project one full round of analysis ambiguity.

Institutional lessons: **(a) when a fix's target halt recurs through an applied fix, re-derive every premise from the current source instead of trusting the previous round's audit — round 9 falsified H13's surviving theory and found the real remaining hole (write side) in the same pass; (b) a halt site is a measurement point, not just a failure — instrument the state around it BEFORE the next field round so the log decides between the surviving theories; (c) builds must self-identify their fix level in their own boot log.**

## H15 — Fix 23: the fix-22 dump catches the real root cause — C pointer-scaling on the D3D upload's typed node pointer: the "null surface" halt read 0x3E0 bytes past the node buffer while the real node was fully seeded (2026-10-27, round 10)

Field: post-fix-22 build (fixset banner present), the `upload-halt 0x16d-surface` dump fired for the first time and decided the round from the log alone:

A halt that tests node+0x10==0 cannot fire while the same node's +0x10 prints non-null ⇒ the check and the dump read DIFFERENT addresses. The dump reads `pCache->pNodeBuffer[nNodeIdx-1]` (C-indexed, byte-exact); the halt check added the raw byte offset (idx*0x20−0x10) to a `D3DTextureCacheNodeStrc*` — and C scales `ptr + int` by sizeof = 0x20, so the true address was base+(idx*0x20−0x10)×0x20: idx 1..6 land inside the seeded buffer on other nodes' `nIndex` (non-zero ⇒ six silent false-passes), idx=7 lands at base+0x1A00 = 0x3E0 bytes PAST the 178×0x20=0x1620 node buffer ⇒ heap zero ⇒ HALT 0x16d.
